### Stored record read, 18:35

The user copied the Mac's iCloud-synced call-history files. They were kept outside this repository and read from a private copy with `sqlite3`.

- **The 12:38 call record:**
  - 11:38:49 UTC, `08451344582`, name `Suspected Spam`, not answered.
  - `ZCOMMUNICATIONTRUSTSCORE = 2`.
  - `ZBLOCKEDBYEXTENSION` empty, `ZJUNKCONFIDENCE = 0`.
  - `ZFILTERED_OUT_REASON` is empty in this synced copy, although the phone logged 4. That field appears not to sync.
- **What 2 means:** decoded by comparison against the rest of the stored call history. 8 = Contact (mostly answered, repeat callers). 5 = Communicated With (numbers the user had also called). 4 = Unknown (the default since iOS 26 arrived in September 2025). Every call since then that carried O2's `Suspected Spam`/`Suspected Scam` name **scored 4**. So did every earlier 0845 call. **Score 2 appears exactly once in the database: on the first 0845 call after our list was installed.** That fits "Blocked By Third Party" and rules out a junk score from O2's label. (evidence: stored record + calibration against the user's own history)
- **Settings screenshot at 18:35:** Screen Unknown Callers = **Never**. Call Filtering "Unknown Callers" = on, which only sorts missed calls into a list. Live Voicemail is on, per the call-time log `isAnsweringMachineAvailable=YES`.

**Conclusion: our list matched the caller.** With unknown-caller screening set to Never, Focus off and Ask Reason not applicable, the matched block is the only input left that explains `shouldSilence YES`. On this iPhone, iOS 26.6.2 turns a Call Directory block into "silence and send to voicemail". Because Live Voicemail is on, the phone answered the call itself and showed its screen. (evidence: stored record + settings screenshot + call-time log. Apple's internal rule is inferred from those inputs; it was not read from Apple's code.)

The second iOS check still disagrees: `blockedByExtension` stayed empty, so Recents does not say which app blocked the call. That inconsistency is Apple's to fix and would be the subject of a Feedback report, which needs the user's approval.

The question has therefore changed. It is no longer only "is the number stored?". It is now "why did iOS silence a caller that our list most likely matched, and why does a second iOS check disagree?".
